# 209. 长度最小的子数组（Minimum Size Subarray Sum）

**难度**：Medium ｜ **Tag**：数组、双指针、滑动窗口

## 题目一句话
给一个**正整数**数组 `nums` 和目标 `target`，求一个**和 ≥ target 的连续子数组**的**最小长度**；不存在返回 0。

## 核心突破口
数组**全为正** → 右扩 `right` 时窗口和只增、左缩 `left` 时只减。对每个 `right`，一旦 `total ≥ target` 就一直缩 `left` 直到再缩就不达标，此刻就是以 `right` 结尾的**最短合法窗口**。

## 思路推导（3 步）
1. **双指针框窗口**：`left`、`right` 同向，`total` 维护窗口和。
2. **右扩**：`total += nums[right]; right++`，把新元素纳入。
3. **左缩**：`while total ≥ target` 时记录 `ans = min(ans, right - left)`，再 `total -= nums[left]; left++`。

## 复杂度
- 时间：O(n)（每个元素最多被 `right` 和 `left` 各访问一次）
- 空间：O(1)

## 一题三问
1. **为什么用 `min` 不是 `max`？**
   题目要"长度最小"的子数组，所以在所有合法窗口里取 **r−left 的最小值**；用 `max` 会得到最长窗口，正好相反。且必须更新到 `ans` 自身（`ans = min(ans, ...)`），否则全局最小留不住。
2. **还能怎么优化？**
   已是最优 O(n) / O(1)；若数组含负数，单调性和滑窗失效，需改前缀和 + 有序容器（见 LC 560）。
3. **换个条件会怎样？**
   - 全正数 → 滑窗 O(n)；
   - 含负数 → 滑窗不成立，转前缀和 + 哈希/有序集合；
   - 要"子数组本身"而非长度 → 记录最短时的 `(left, right)`（如你第一版思路）。
