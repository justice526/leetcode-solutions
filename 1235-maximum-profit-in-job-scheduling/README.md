# 1235. 规划兼职工作（Maximum Profit in Job Scheduling）

**难度**：Hard ｜ **Tag**：动态规划、二分、排序

## 题目一句话
给 n 个区间 `[startTime, endTime, profit]`，选一组**互不重叠**（背靠背允许，即 `end ≤ start` 即可）的区间，使利润和最大。

## 核心突破口
按**结束时间**排序后，每个区间只有两条路：选它 / 不选它；用二分找「最后一个不重叠的前驱」做到 O(1) 转移。

## 思路推导（3 步）
1. **排序**：按结束时间升序（`zip(endTime, startTime, profit)` 让 endTime 排首位）。
2. **二分找前驱 p**：对区间 i，找最后一个 `end ≤ start_i` 的下标 `p = bisect_right(ends, start) - 1`。
3. **DP**：`dp[i] = max(dp[i-1], profit_i + dp[p+1])`
   - `dp[i-1]`：不选区间 i（继承前 i-1 个的最优）
   - `profit_i + dp[p+1]`：选区间 i，只能叠在「结束 ≤ 开头」的前驱最优上

## 复杂度
- 时间：O(n log n)（排序 + 每轮二分）
- 空间：O(n)

## 一题三问
1. **为什么选 i 时加的是 dp[p(i)] 而不是 dp[i-1]？**
   选区间 i 后，所有与它重叠的区间都不能再要，只能叠加在「结束 ≤ 开头」的那些区间上，`dp[p]`（1 基里是 `dp[p+1]`）正是这些里的最优；`dp[i-1]` 是「不选 i」的另一条分支，两条取 max。
2. **还能怎么优化？**
   空间已是最优 O(n)——dp 需要随机访问 `dp[p+1]`，必须保留整张表，无法滚动压缩。
3. **换条件会怎样？**
   - 「共享端点也算重叠」（LC 3414）→ 二分 `bisect_right` 改成 `bisect_left`；
   - 「最多 k 个区间」（LC 1751 / 3414）→ dp 升级成二维 `dp[i][k]`。
