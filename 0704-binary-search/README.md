# 704. 二分查找（Binary Search）

**难度**：Easy ｜ **Tag**：数组、二分查找

## 题目一句话
在一个**升序**数组 `nums` 里找 `target`，找到返回下标，找不到返回 `-1`。

## 核心突破口
数组**已排序** → 每次取中点比较，能**砍掉一半**搜索区间，把 O(n) 降到 O(log n)。代价是必须先有序（本题已保证）。

## 思路推导（3 步，关键在"区间模板"）
1. **定区间**：用**半开区间** `[l, r)`，`l=0, r=len(nums)`（r 是开边界，不含）。
2. **取中点比较**：`mid = l + (r-l)/2`（防溢出写法）。
   - `nums[mid] == target` → 命中，返回 `mid`；
   - `>` → 目标在左半，`r = mid`（开区间，mid 已排除）；
   - `<` → 目标在右半，`l = mid + 1`（**必须 +1**）。
3. **循环条件**：`while (r != l)`（或 Python `while l < r`），区间空了还没找到 → 返回 `-1`。

## 复杂度
- 时间：O(log n)
- 空间：O(1)

## 一题三问
1. **为什么 `l = mid` 会死循环、`l = mid + 1` 才对？**
   当窗口只剩 2 个下标（`l=3, r=4`），`mid = (3+4)/2 = 3`；若 `nums[3] < target` 写成 `l = mid = 3`，l、r 都不变 → `while` 永不退出。写 `l = mid + 1` 保证左边界越过 mid、区间严格缩小。
2. **还能怎么写？**
   另一种常见模板是**闭区间** `[l, r]`（`r = len-1`、`while l <= r`），此时右缩要 `r = mid - 1`。两套别混。
3. **换个条件会怎样？**
   - 要"第一个 ≥ target 的位置" → 改成 `bisect_left`（LC 35 搜索插入位置）；
   - 数组有重复且要找左右边界 → LC 34 在二分基础上加"收缩"；
   - 无序数组 → 二分失效，只能线性扫或先排序 O(n log n)。
