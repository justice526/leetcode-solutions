# LC 1751 · 最多可以参加的会议数目 II

- **难度**：Hard
- **标签**：数组 / 二分查找 / 动态规划 / 排序

## 题意（一句话）

从 `events[i] = [start, end, value]` 中选出**最多 k 个互不重叠**的会议，使价值之和最大。

> ⚠️ 陷阱：结束日是**闭区间**——"同一天不能既结束又开始"，即 `end == start` 算**冲突**。

## 核心突破口

1. **按结束时间排序**后，任意会议的"前驱（最后一个与它不冲突的会议）"一定是**连续前缀** → 可以用**二分** O(log n) 定位。
2. 比 LC1235 多了"**最多 k 个**"的限制 → 一维 `dp[i]` 里存不下"已用几个名额" → **必须补一维**专门记录名额用量。

## 状态与转移

- **状态**：`dp[i][j]` = 前 `i` 个会议中，**最多**选 `j` 个能获得的最大价值。
- **转移**：站在第 `i` 个会议（0-based 下标 `i`）面前，两条路取大：
  - 不选它：`dp[i][j]`
  - 选它  ：`dp[p][j-1] + w`，其中 `p = lower_bound(ends, start) - begin()`（结束时间**严格 <** 当前开始时间的会议个数；选它用掉一个名额，故第二维 `-1`）
- **答案**：`dp[n][k]`

## 复杂度

- 时间：`O(n log n + n·k)`（排序 + 每个会议二分 + 二维 DP）
- 空间：`O(n·k)`

## 一题三问

**1. 为什么这样做？**
三个约束叠加——"不重叠 + 最多 k 个 + 价值最大"。排序保证前驱是前缀（可用二分）；`k` 的限制要求知道"名额用量"，故加第二维。

**2. 还能怎么优化？**
时间已是 `O(n log n + nk)`，受制于 `k·n ≤ 10⁶` 的约束，够用。空间 `O(nk)` 基本不可避免，因为 `dp[i+1]` 要访问任意小的 `dp[p]`（`p ≤ i`），无法简单滚动成一维。

**3. 换个条件会怎样？**
- 若"**端点可重合**"（如 LC1235）→ 改用 `upper_bound`。
- 若 **k 无上限** → 退化成 LC1235 的一维 DP。
- 若要求"**恰好 k 个**" → 转移需改（或初始化为 `-inf`，不能随意跳过）。
- 若要求返回"**字典序最小的下标集**"（如 LC3414）→ 需额外保存下标并做 tie-break。

## 相似题

- **LC1235 规划兼职工作**（同族 · 一维 · `end <= start` 可重合 → `upper_bound`）
- **LC3414 不重叠区间的最大得分**（同族 · 固定 ≤ 4 个 · 严格不重叠 · 字典序最小 → 需 `long long`）
